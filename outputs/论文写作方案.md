# 论文写作方案

> 题目：基于 Spring Boot 的 AI 培训计划管理系统设计与实现
> 定位：稳过型。结构规范、图表充足、实验有真数据，不追求理论深度。
> 按 1.8 万字规划（多数本科毕设要求 1.2–2 万字，按学校要求等比缩放即可）。

---

## 一、先记住三条原则

1. **老师最先看的是目录和图表，最后才看正文。** 目录层级乱、图少，第一印象就低了。图表数量建议 18–25 张。
2. **每张图都要在正文里被"叫到"。** 不能有孤图。"如图 4-3 所示"这句话必须出现。
3. **数据必须是真的。** 系统里跑出来的才能写，编的数据在答辩时一追问就露。

---

## 二、章节骨架与字数分配

| 章节 | 标题 | 字数 | 核心任务 |
| --- | --- | --- | --- |
| 摘要 | 中英文各一份 | 500 | 背景 → 做了什么 → 怎么做的 → 结果 |
| 第 1 章 | 绪论 | 2000 | 背景与意义、国内外现状、研究内容、论文结构 |
| 第 2 章 | 相关技术 | 1200 | **只写你实际用到的**，别抄框架原理 |
| 第 3 章 | 需求分析 | 3000 | 可行性、功能需求（六模块）、非功能需求、用例 |
| 第 4 章 | 系统设计 | 4000 | 总体架构、模块设计、数据库设计、**AI 模块设计（重点）** |
| 第 5 章 | 系统实现 | 4000 | 分模块讲实现 + 界面截图 + 关键代码 |
| 第 6 章 | 系统测试 | 2500 | 功能测试、性能测试、**闭环效果验证（重点）** |
| 第 7 章 | 总结与展望 | 800 | 做完了什么、不足、后续可做 |
| — | 参考文献 | 15–20 篇 | 近 5 年为主，中英文各半 |

**配比提示**：第 4、5 章合起来占全文 45%，这是"设计与实现"类题目的重心；第 2 章千万别超过 1200 字，写多了像凑字数，还容易查重。

**4.3 差距量化模型**（这段直接决定了论文有没有"设计"的味道）：

```
gap(i)         = max(0, target(i) − current(i))          等级差距
weightedGap(i) = gap(i) × weight(i)                       加权差距
priority(i)    = weightedGap(i) / max(weightedGap) × 100  优先级得分
matchRate      = 1 − Σ weightedGap(i) / Σ(target(i) × weight(i))   达标率
```

写完公式**一定要举一个具体例子算一遍**（拿系统里真实数据，比如"陈静，质量工程师，6 项技能中 3 项有差距，达标率 77.29%"）。有一个算例，这章就立住了。

**4.4 AI 方案生成**（论文的创新点所在，要写透）：

按这四层写：

1. **为什么要混合**：纯 LLM 的三个问题——课程可能不在课程库（幻觉）、顺序可能违背先修关系、结果不可复现
2. **规则层做什么**：按加权差距降序召回候选课程、按差距大小分配学时、约束总学时不超过预算
3. **LLM 层做什么**：只基于候选课程和真实差距数据，生成方案说明与学习路径，不允许自行增删课程
4. **可控性设计**：强制 JSON 输出 → Schema 校验（课程存在性、学时合计、技能点来源）→ 失败重试 → 仍失败则降级为纯规则方案

配一张**状态流转图**（图 4-4）：请求进来 → 有无 API Key → 调用 → JSON 解析 → Schema 校验 → 通过（AI_HYBRID）/ 任一环节失败（AI_RULE）。这张图答辩时能直接指着讲。

**4.5 数据库设计**：
- E-R 图：用 `outputs/数据库设计-DDL.sql` 在 Navicat / draw.io 里反向生成，25 张表不用全画，画 8–10 张核心表的关系即可
- 表结构：核心表用**三线表**列字段（字段名、类型、允许空、说明），不用 25 张全列，列 sys_user、post、skill、post_skill、emp_skill、train_plan、exam_paper、ai_gen_record 这 8 张

> - **选择 A（安全）**：实验只写上面这组真实闭环数据 + 功能/性能测试。混合策略在第 4 章作为"设计"论证，不写成"实验结果"。**这是完全站得住的写法。**

## 五、写作顺序（别从第一章开始写）

按这个顺序写，阻力最小：

```
第 1 步  第 3 章 需求分析      ← 开题文档直接扩写，最快出活
第 2 步  第 4 章 系统设计      ← DDL 在手，E-R 图能直接生成
第 3 步  第 5 章 系统实现      ← 系统已跑起来，边截图边写
第 4 步  第 6 章 系统测试      ← 跑脚本拿数据，编测试用例
第 5 步  第 2 章 相关技术      ← 半小时的事，最后写
第 6 步  第 1 章 绪论          ← 需要"包装"，先看完全文再写更准
第 7 步  第 7 章 + 摘要        ← 摘要最后写，从各章结论里摘
第 8 步  参考文献 + 格式统一    ← 用 EndNote / Zotero 管，别手打
```

**理由**：第 3、4、5 章占了 60% 篇幅且素材全在手边，先把大头干掉，心理压力立刻小一半。绪论要"拔高"，写在最后反而更容易。

## 七、常见扣分点（逐条自查）

| 扣分点 | 怎么避 |
| --- | --- |
| 摘要写成"流水账" | 按「背景 → 问题 → 方法 → 结果 → 意义」五句写，结果要有数字 |
| 图没有编号/没有正文引用 | 每张图都要有"如图 x-x 所示"，且图在前文之后出现 |
| 代码大段粘贴 | 单段 ≤ 30 行，只贴核心逻辑 |
| 第 2 章抄框架官网 | 全用自己的话写选型理由，控制在 1200 字 |
| 表格没表头/没三线 | 统一三线表，表题在表上方，图题在图下方 |
| 实验数据无来源说明 | 明确写"数据由系统闭环测试脚本生成，见附录" |
| 展望章写"由于时间有限" | 换成"后续可在以下方向深化"，写具体方向 |
| 中英文摘要不一致 | 英文摘要最后翻译，别各写各的 |
| 页眉页脚/页码/行距不统一 | 交稿前用学校模板刷一遍格式，这是最冤的扣分 |
