## 三、本轮新发现

### 3.1 试卷未做归属校验（中低危，已修）

- **现象**：员工 `emp002` 用 `GET /api/exam/paper/1` 能取到试卷 1 的全部 9 道题。试卷 1 属于「AI 个性化培训-冯桂英」（`plan_id=2`，目标学员只有 `emp001`）。
- **危害**：不含答案与解析（这点原设计做对了），但员工可按 id 递增遍历到别人计划下的试卷，**提前看题**；开考与交卷同样不校验，可对任意试卷生成作答记录——第一轮发现的「2 条 0 分空作答」很可能就是这样产生的。
- **根因**：`exam_paper` 表没有考生字段，只有 `plan_id`；`paperForExam` / `startExam` / `submit` 三个入口都没有拿 `plan_id` 去反查学员范围。
- **修复**：
  1. `TrainPlanService` 新增 `isTargetUser(planId, userId)`，复用已有的 `resolveTargetUsers`（PERSONAL / DEPT / POST / BATCH 四种口径都覆盖）；
  2. `ExamService` 新增 `assertPaperAccessible(paper)`，在取卷、开考、交卷三处调用；
  3. 管理员与讲师不受限；`plan_id` 为空的自由组卷试卷无法判定归属，保持放行（避免误伤）。
- **复测**：

```
emp001（plan 2 的目标学员）GET /exam/paper/1 -> code=0  success
emp002（非该计划学员）      GET /exam/paper/1 -> code=403 该试卷不属于你的培训计划
admin                      GET /exam/paper/1 -> code=0  success
```

### 3.2 培训需求可伪造提交人（低危，已修）

- **现象**：`emp001` 提交 `POST /api/train/need`，请求体里带 `submitterId=2`（讲师陈静），接口返回成功；查库确认 `submitter_id` 存的是 **2**，即冒用了讲师名义。
- **危害**：需求池里出现「以他人名义提报」的记录，审核人无法追溯真实来源；被冒名的讲师也可能被追责。
- **根因**：`saveNeed` 只在 `submitterId` 为空时才填当前用户，非空则原样落库。
- **修复**：员工提报时**强制覆盖**为当前用户；讲师 / 管理员保留代提能力（业务上需要）。同时堵住修改路径——员工 `updateById` 前把 `submitterId` 置空，避免把自己提的需求改成别人的。
- **复测**：同样带 `submitterId=2` 提交，落库 `submitter_id=5`（emp001 本人），冒名失败。

### 3.3 CORS 放开任意来源并允许携带凭证（低危，已修）

- **现象**：带 `Origin: https://evil.example.com` 请求，响应头回显
  `Access-Control-Allow-Origin: https://evil.example.com`、`Access-Control-Allow-Credentials: true`。
- **危害**：任何第三方站点都能跨域读取接口响应。本项目令牌走 `Authorization` 头、存 localStorage，第三方拿不到令牌，**当前无法直接利用**；但一旦将来引入 Cookie 会话，这套配置会立刻变成 CSRF 通道。
- **修复**：`allowedOriginPatterns` 收敛为 `http://localhost:[*]` 与 `http://127.0.0.1:[*]`，保留本机任意端口（答辩换端口不受影响）。
- **复测**：

```
Origin: https://evil.example.com  -> 无 Access-Control-Allow-Origin（浏览器会拒绝读取）
Origin: http://localhost:3000     -> ACAO=http://localhost:3000  ACAC=true（前端正常）
```

### 3.4 保留项（评估后不改）

| 项 | 现状 | 理由 |
|---|---|---|
| 部门 / 岗位 / 角色列表对员工开放 | 三个接口均返回 200，员工可读 | 全局字典，员工端「我的技能差距」「提需求」等表单的下拉需要它；组织架构不属于个人隐私，且所有请求仍需登录 |
| `/ai/status` 暴露模型名与是否可用 | 返回 `model=deepseek-chat`、`llmAvailable` | 不含 API Key、不含接口地址；前端要靠它决定是否禁用「混合」模式，属功能性返回 |

## 四、接口权限矩阵（81 个接口全量遍历）

按模块归纳，不逐个罗列：

| 模块 | 读接口策略 | 写接口策略 |
|---|---|---|
| 认证 `/auth` | 登录 / 登出 / 当前用户 | 无需权限（登录本身除外） |
| 用户 `/system/user` | 分页与详情：管理员或讲师；本人可查自己 | 新增 / 删除 / 重置密码：管理员 |
| 组织 `/system` | 部门 / 岗位 / 角色列表：登录即可 | 增删：管理员 |
| 技能 `/skill` | 字典与岗位模型：登录即可；员工档案与差距：本人或管理者 | 技能点维护：讲师以上；删除：管理员；档案与需求：本人或管理者 |
| 培训需求 `/train/need` | 员工只见自己提报的（SQL 层过滤） | 提交：本人名义；审核：讲师以上；删除 / 修改：本人或管理者 |
| 课程 `/train/course` | 登录即可 | 新增：讲师以上；删除：管理员 |
| 培训计划 `/train/plan` | 员工只见与自己相关的（按 PERSONAL / DEPT / POST / BATCH 四口径过滤），详情另有归属校验 | 保存 / 状态流转 / 删除：讲师以上 |
| 进度 `/train/progress` | 我的任务：仅本人；计划明细 / 看板 / 风险：讲师以上 | 上报：仅本人记录，且计划须处于进行中 |
| 题库 `/exam/question` | 全部讲师以上 | 全部讲师以上 |
| 试卷 `/exam` | 列表：讲师以上；取卷：**本轮新增归属校验** | 组卷 / 开考 / 交卷：组卷讲师以上，开考交卷限本计划学员 |
| AI `/ai` | 状态与生成：登录即可（生成限本人）；记录 / 指标 / 提示词：讲师以上 | 采纳 / 盲评 / 效果 / 知识库：讲师以上 |
| 知识库 `/ai/kb` | 文档与片段：讲师以上 | 上传 / 删除 / 重建索引：讲师以上 |

结论：**写操作没有遗漏**，读操作此前有 3 处缺口（用户分页、用户详情、试卷），前两处第一轮已修，本轮补上第三处。

## 五、配置与产物面

| 检查 | 结果 |
|---|---|
| 打包产物是否夹带 `application-local.yml` | 否。jar 内只有 `BOOT-INF/classes/application.yml`；口令文件在 server 根目录，靠 `spring.config.import` 相对路径加载，不打进包 |
| 数据库口令兜底 | 无明文兜底，`${DB_PASSWORD:}` 为空则启动即连库失败，不会静默用弱口令 |
| 文件上传 | 全仓库无 `MultipartFile`，不存在上传目录与路径穿越面；知识库文档是种子数据入库 |
| 前端 sourcemap | `vite.config.ts` 未开启 `build.sourcemap`，生产产物不含源码映射 |
| 日志落盘 | 无 `logback-spring.xml`，日志仅控制台；不存在「日志文件落在静态目录被下载」的风险 |
| Actuator | 未引入 `spring-boot-starter-actuator`，无 `/actuator/env` 之类端点 |
| 依赖 | 仅 web / validation / mybatis-plus / mysql / sa-token / security-crypto / knife4j / hutool，无 fastjson、无 log4j |
| 令牌策略 | 24 小时有效，`active-timeout=-1`（不因闲置提前失效），`is-concurrent=true`（可多端同时登录） |

## 六、剩余建议（非本次改动范围）

1. **接口文档匿名可读**：`/doc.html`、`/v3/api-docs` 在放行名单里，答辩需要现场展示，保留。正式上线应加登录校验或直接关闭。
2. **令牌 24 小时 + 无闲置超时**：毕业设计够用；若对外，建议缩短到 2 小时并开启 `active-timeout`。
3. **Spring Boot 3.3.x 已过开源支持窗口**：本机不对外，风险可接受；正式上线应升级到当前受支持版本。
4. **数据库以 root 直连**：毕设环境单机自用可接受；上线应建最小权限账号（只给 `ai_training` 的读写）。
5. **前端目录下的 `.backup-src-*`、`.backup-dist-*`**：是历史备份，不影响运行，但**不要随前端产物一起部署**，否则等于把源码交出去。
