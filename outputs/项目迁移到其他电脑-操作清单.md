# 项目迁移到其他电脑 — 操作清单

> 适用：把本毕设从当前电脑搬到另一台 Windows 电脑上跑起来。
> 项目位置：`C:\Users\梦萦\Documents\Codex\2026-10-14\bi`

---

## 一、复制哪个文件夹

**复制整个 `bi` 文件夹**：

```
C:\Users\梦萦\Documents\Codex\2026-10-14\bi
├── outputs\          文档（开题总结、DDL、论文方案、答辩口径、零基础讲解）
└── work\app\         代码与启动脚本
    ├── server\       Spring Boot 后端（含 sql 初始化脚本）
    ├── web\          Vue 前端
    ├── start-all.bat
    ├── start-mysql.bat
    ├── start-backend.bat
    ├── start-frontend.bat
    ├── db-shell.bat
    └── README.md
```

复制到新电脑任意位置都行（**建议纯英文路径**，如 `D:\ai-training-bi`），
因为 `start-*.bat` 全部用 `%~dp0` 相对定位，不需要改路径。

---

## 二、这三样必须排除（复制的坑）

| 排除项 | 位置 | 原因 |
|---|---|---|
| `node_modules` | `work\app\web\node_modules` | 几百 MB、文件数极大，复制极易失败；新电脑 `npm install` 重装更干净 |
| `.backup-*` | `work\app\web\.backup-dist-*`、`.backup-src-*` | 清理死代码时的备份，纯垃圾，约 3 MB |
| `dist` | `work\app\web\dist` | 前端构建产物，新电脑重新 build 即可 |

可选保留：`work\app\server\target\ai-training-server-1.0.0.jar`（约 41 MB）。
带上可以省一次打包，不带也没关系，`mvn package` 能重新生成。

> 用资源管理器复制时，最稳的做法是**先删掉这三类，再整体复制**，避免复制到一半卡死。

---

## 三、数据库不在项目文件夹里

原始数据目录在 `D:\develop\mysql-data\ai-training`（约 199 MB），**不要复制它**。
跨机器拷贝 MySQL 数据文件容易因版本、字符集、redo log 状态出问题。

正确做法是**用项目自带的 SQL 重建**：

```
server\sql\01-schema.sql     建表（25 张）
server\sql\02-seed.sql       初始化数据（用户、岗位、技能、课程、题库等）
```

---

## 四、新电脑需要装什么

| 依赖 | 版本要求 | 用途 |
|---|---|---|
| JDK | **21**（必须） | 项目用 Java 21 编译，17 会编译失败 |
| Maven | 3.9+ | 打包后端；用 IDEA 打包也可以 |
| Node.js | **20.19+ 或 22.12+**（硬要求） | `web/package.json` 的 `engines` 明确限制，低于此版本 `npm install` 会报 EBADENGINE 并失败 |
| MySQL | 8.0 | 数据库 |

装完确认：

```cmd
java -version
mvn -v
node -v
mysql --version
```

> Node 版本是这次迁移最容易踩的坑：这台电脑是 24.18.0，完全够用；
> 新电脑如果装的是 18.x 或 20.10 以下，前端起不来。**推荐直接装 Node 22 LTS**。

## 五、迁移步骤（照着做）

### 第 1 步：建库并导入数据

用 MySQL 命令行或 Navicat 执行：

```sql
CREATE DATABASE ai_training DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

然后导入（在 `work\app\server` 目录下执行）：

```cmd
mysql -uroot -p ai_training < sql\01-schema.sql
mysql -uroot -p ai_training < sql\02-seed.sql
```

验证：

```sql
USE ai_training;
SHOW TABLES;                    -- 应为 25 张
SELECT COUNT(*) FROM sys_user;  -- 应为 64
```

### 第 2 步：改数据库密码

打开 `work\app\server\src\main\resources\application.yml`，
把 `spring.datasource.password` 改成**新电脑 MySQL 的 root 密码**。

> 端口、库名一般不用改（`127.0.0.1:3306/ai_training`）。如果新电脑 MySQL 不在 3306，
> 同步改 `url` 里的端口。

### 第 3 步：改 `start-mysql.bat` 里的两行硬编码

这个脚本写死了当前电脑的路径，换机器后**必然失效**，必须改：

```bat
set MYSQLD=D:\develop\MySQL\MySQL Server 8.0\bin\mysqld.exe
set MYCNF=D:\develop\mysql-data\conf\ai-training.cnf
```

两种处理方式，**任选其一**：

**方式 A（简单）**：新电脑把 MySQL 装成正常服务（默认 `MySQL80`），开机自启。
那么 `start-mysql.bat` **不需要用**，直接跳过它，其他脚本照旧。

**方式 B（照搬隔离实例）**：把原来 `D:\develop\mysql-data\conf\ai-training.cnf`
和整个 `D:\develop\mysql-data\ai-training` 数据目录也复制过去（这种属于完整克隆，
如果 MySQL 版本完全一致才能用），然后修正上面两行路径。

> **推荐方式 A**：新电脑装一个标准 MySQL 8.0 服务，用 SQL 脚本建库。
> 这样路径全默认，没有额外配置文件要维护，答辩换电脑最省事。

### 第 4 步：启动后端

```cmd
cd work\app\server
mvn package -DskipTests
java -jar target\ai-training-server-1.0.0.jar --server.port=8000
```

或者开发模式：

```cmd
mvn spring-boot:run
```

> **必须显式带 `--server.port=8000`**：本项目 yml 里虽然写的是 8000，
> 但如果新电脑存在同名环境变量 `SERVER__PORT`（值为 0），会覆盖配置导致随机端口。

看到这两行算成功：

```
Tomcat started on port 8000 (http)
Started AiTrainingApplication in X seconds
```

### 第 5 步：启动前端

```cmd
cd work\app\web
npm install
npm run dev
```

访问 http://localhost:3000

默认账号：`admin` / `lecturer01`（张三）/ `emp001`（李四），密码统一 `123456`。

## 六、已知坑（换电脑后最容易撞的）

| 现象 | 原因 | 解决 |
|---|---|---|
| `找不到或无法加载主类 com.aitraining.AiTrainingApplication` | 中文用户名目录下，Spring Boot 插件用 UTF-8 写 argfile、JVM 按 GBK 读 | pom 里插件已固定 3.2.11（不受影响）；若仍出现，改用 `java -jar` |
| `Access denied for user 'root'` | 没改 `application.yml` 的密码 | 回第 2 步 |
| `Unknown database 'ai_training'` | 没建库或没导入 SQL | 回第 1 步 |
| `Port 8000 was already in use` | 端口被别的程序占用 | 换端口启动 `--server.port=8001`，同时改 `web/vite.config.ts` 第 39 行的 `target: "http://127.0.0.1:8000"` |
| 页面能开但数据全空 | 后端没起或数据库空 | 先看后端控制台是否报错 |
| 前端 `npm install` 卡住或报错 | 网络（npm 源）或 Node 版本过低 | 换淘宝源 `npm config set registry https://registry.npmmirror.com` |

## 七、迁移后自查（30 秒验证）

```cmd
REM 1. 三个端口都在监听
netstat -ano | findstr ":3306 :8000 :3000"

REM 2. 后端接口有响应（401 属正常，说明服务活着）
curl http://127.0.0.1:8000/api/ai/status

REM 3. 前端页面 200
curl -o nul -w "%{http_code}" http://127.0.0.1:3000/
```

浏览器打开 http://localhost:3000，用 `admin / 123456` 登录，
工作台能看到「培训计划 2 个、完成率 53.77%」就说明数据完整迁移成功。

## 八、如果要给老师演示（不换机器场景）

在新电脑上答辩演示，最稳的是先跑一遍 `start-all.bat`，确认：

1. 它会自动检测 3306，没起就调 `start-mysql.bat`
2. 后端窗口出现 `Started AiTrainingApplication`
3. 浏览器 http://localhost:3000 能登录

`start-all.bat` 依赖 `start-mysql.bat` 里的硬编码路径，所以按第 3 步的方式 A 处理过之后，
建议直接**手动依次启动三个窗口**（MySQL 服务 → 后端 → 前端），比依赖 bat 更可控。
