## 二、已修复的四项

### 2.1 用户分页未授权（中危）

- **修复前**：`GET /system/user/page` 用员工令牌返回 `code=0`，`total=64`，单条含 `phone`、`email`、`roles`。
- **根因**：`UserController` 的写操作在 `UserService` 里都调了 `requireAdmin()`，唯独 `page()` 与 `detail()` 漏了校验。
- **修复**：`UserService.page()` 加 `LoginHelper.requireManager()`。

### 2.2 用户详情水平越权（中危）

- **修复前**：员工用 `GET /system/user/3` 可读他人详情。
- **修复**：`UserService.detail()` 加 `LoginHelper.requireSelfOrManager(id)`——本人可查自己，查他人需管理员或讲师。
- **兼容性**：前端仅管理端用户页调用该接口，员工端个人中心走 `/auth/me`，不影响现有页面。

### 2.3 登录爆破（中危）

- **修复前**：连续 8 次错误口令均返回「密码错误」，无锁定、无限流；且「账号不存在」与「密码错误」分开提示，可用来枚举有效用户名。
- **修复**：新增 `LoginAttemptService`，按账号计数，连续 5 次失败锁定 10 分钟；两类失败统一为「账号或密码错误」。
- **实现取舍**：键只取用户名不叠加 IP，因为校园网出口 IP 相同会误伤；单机内存实现，多实例部署需换 Redis。

### 2.4 异常信息外泄（低-中危）

- **修复前**：500 返回 `系统繁忙：Request method 'GET' is not supported`，直接暴露框架行为与内部路径。
- **修复**：对外只返回 `系统繁忙，请稍后重试（错误码 xxxxxxxx）`，完整堆栈按 traceId 落日志，便于定位又不泄露结构。

## 三、修复验证（实测输出）

```
1. 员工拉用户列表      -> code=403 该操作仅管理员或讲师可用
2. 员工查他人详情      -> code=403 只能查看或操作自己的数据
3. 员工查自己详情      -> code=0 success
4. 管理员拉用户列表    -> code=0 success（未误伤）
5. 触发异常            -> code=500 系统繁忙，请稍后重试（错误码 dab5102f）
6. 连续错误登录第 6 次 -> code=429 密码错误次数过多，请 10 分钟后再试
```

单元测试 49 个全绿（原有 45 + 新增 4 个限流用例）。

## 四、保留项与理由

| 项 | 现状 | 为什么暂不改 |
|---|---|---|
| 接口文档未认证可读 | `GET /v3/api-docs`、`/doc.html` 返回 200 | 答辩需要现场展示接口文档；且只暴露接口签名，不含数据。若正式上线，应加登录校验或关闭 |
| 令牌存 localStorage | 前端 `stores/user.ts` | 改 HttpOnly Cookie 需重做跨域与 CSRF 方案，工程量远大于收益；当前无 `v-html`，XSS 面很小 |
| 默认口令 123456 | 演示账号 | 毕设演示需要，已在文档标注；生产必须强制首次改密 |
| 重置密码仅管理员 | `requireAdmin()` | 员工无法自助改密，属功能欠缺而非漏洞，本次不动 |

## 五、环境备注

自查时 3306 被系统服务 MySQL80 占用（其数据目录无 `ai_training` 库），后端启动报 `Unknown database`。
为避免停掉系统服务影响其他库，本次让项目实例临时监听 **3307**，后端用 `--spring.datasource.url` 覆盖连接串：

```bash
mysqld --defaults-file="D:/develop/mysql-data/conf/ai-training.cnf" --port=3307 --console
java -jar target/ai-training-server-1.0.0.jar --server.port=8000 \
  --spring.datasource.url='jdbc:mysql://127.0.0.1:3307/ai_training?...'
```

这是临时规避，不改任何配置文件。要恢复常态，仍需把 `MySQL80` 服务改为「手动」启动，
然后用项目自带的 `start-all.bat`（脚本会自己判断 3306 上的实例归属）。
