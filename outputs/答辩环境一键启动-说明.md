# 答辩演示环境 · 一键启动说明

## 一句话

双击 `work\app\start-demo.bat`，等 10–50 秒，浏览器自动打开，用 `admin / 123456` 登录。

结束演示就双击 `work\app\stop-demo.bat`。

---

## 它做了什么

| 步骤 | 动作 | 失败时的表现 |
|---|---|---|
| 0 | 检查 java、jar、前端依赖、数据库配置、mysql 客户端 | 明确指出缺哪一项，停在这一步 |
| 1 | 找数据库：3306 是不是本项目的库？不是就看 3307；都没有就在 3307 起一个 | 40 秒内连不上则中断，提示看 MySQL 窗口 |
| 2 | 启动后端（8000），等它真的能响应 HTTP | 90 秒无响应则中断，并记录现场到 trace |
| 3 | 前端产物存在就直接起预览服务（3000），不存在先构建 | 40 秒无响应则中断 |
| 4 | 汇总两个服务的 HTTP 状态与耗时 | — |
| 5 | 打开浏览器 | — |

启动成功时最后会显示：

```
================================================================
   环境已就绪

   访问地址   http://127.0.0.1:3000
   登录账号   admin / 123456
   数据库     127.0.0.1:3307
================================================================
```

数据库端口不固定，脚本会自己判断并显示实际值。

---

## 为什么不用原来的 start-all.bat

原来那套是开发时用的，答辩当天会在这几个地方翻车：

| 问题 | 旧脚本 | start-demo.bat |
|---|---|---|
| 3306 被系统 MySQL80 抢占 | `start-mysql.bat quiet` 直接退出，后端随后报 `Unknown database` | 自动退到 3307，不碰系统服务，不需要管理员权限 |
| 前端启动方式 | `npm run dev`，本机因删除临时目录触发沙箱策略必崩 | 预构建产物 + `vite preview` |
| 启动顺序 | 后端和前端同时起，不等就绪 | 库 → 后端 → 前端，逐级等待并探测 |
| 工作目录 | `java -jar` 在 `work\app` 下执行，读不到 `server\application-local.yml`，数据库密码为空 | 显式切到 `server` 目录再启动 |
| 旧进程残留 | 不清理，可能连到上次的实例却看不出来 | 先杀掉 8000/3000 上的旧进程再启动 |
| 出错后 | 窗口闪退，什么也看不到 | 窗口保持（`/k`），并写 trace 文件 |

---

## 出问题时看哪里

**1. 看屏幕上停在第几步**

脚本每一步都打印 `[n/5]`，中断时会打印「启动中断」并列出常见原因。

**2. 看 trace 文件**

```
work\app\logs\start-demo-trace.log
```

里面记录了每次启动的时间、实际用的数据库端口、启动命令、java 进程是否活着、等待了多少轮。典型内容：

```
================ 2026/11/26 周四 21:38:23.67 启动 ================
[start] cwd=...\work\app\server jar=target\ai-training-server-1.0.0.jar port=8000
[dbport] 3307
[proc] java PID=24144
[wait_be] 共等待 1 轮
```

`[wait_be] 共等待 45 轮` 表示后端 90 秒都没起来，去看「AI培训-后端」窗口。

**3. 看服务窗口**

- 「AI培训-后端(8000)」：后端日志，启动失败会停在这里
- 「AI培训-前端(3000)」：预览服务日志
- 「AI培训-MySQL(3307)」：只在脚本自己起数据库时出现

## 常见情况

**问：能不能直接访问 3306 上的数据库？**

如果 3306 上跑的是本项目的实例，脚本会直接用 3306，不用另起。判断依据是连上去执行 `show databases like 'ai_training'`，查得到才算。

**问：改了前端代码需要重新构建吗？**

需要。删掉 `web\dist-demo` 目录，或运行 `start-demo.bat rebuild`。

**问：关闭时要不要连数据库一起停？**

默认不停，因为下次启动要重新等它起来。要一起停用 `stop-demo.bat all`（只停 3307，不动系统 MySQL80）。

**问：第一次启动为什么慢？**

首次要构建前端产物（约 40 秒）。构建一次后，后续启动约 12 秒。

## 实测数据

| 场景 | 数据库 | 后端 | 前端 | 结果 |
|---|---|---|---|---|
| **冷启动**（模拟开机，库也没起） | 10.0 秒 | 18.1 秒 | 21.1 秒 | 登录成功，用户表 64 条 |
| 热启动（前端产物已存在） | 已就绪 | 12.1 秒 | 12.1 秒 | 登录成功，用户表 64 条 |
| 首次（需构建前端） | 已就绪 | 8.2 秒 | 47.3 秒 | 登录成功，用户表 64 条 |

「用户表 64 条」这个数字是用来看是否连对了库的：连到没有数据的库时，登录会失败或列表为空。

冷启动那行是拿 `stop-demo.bat all` 把数据库、后端、前端全停掉之后测的，等同于答辩当天开机的状态。

## 答辩前一天建议做一次

1. 双击 `start-demo.bat`，确认浏览器自动打开且能登录
2. 按「工作台 → 技能差距分析 → AI 方案生成 → 效果诊断 → 进度看板」走一遍
3. 双击 `stop-demo.bat` 关掉
4. 再双击一次 `start-demo.bat`，确认第二次也正常（模拟答辩当天）

第 4 步很重要：答辩当天是冷启动，和开发时热着的状态不一样。

## 建议：把系统 MySQL80 改为手动（一次性，做完就不用再管）

本机 3306 上有两套 MySQL：系统服务 `MySQL80`（开机自启，数据目录里没有本项目库）与项目独立实例。MySQL80 先占住 3306，脚本就只能退到 3307。

把它改成「手动」之后，开机时 3306 是空的，项目实例可以直接用 3306，少一层探测，也不会出现两个 MySQL 窗口。

**操作**：双击 `work\app\mysql80-manual.bat`，弹窗点「是」授权，选择：

- `1` 只改启动类型，服务继续运行（推荐，下次开机才生效）
- `2` 改启动类型并立即停止服务（现在就把 3306 让出来）

改完之后：

| 要做的事 | 操作 |
|---|---|
| 启动项目数据库 | 双击 `start-mysql.bat`（用 3306 起项目实例） |
| 启动全套演示环境 | 双击 `start-demo.bat`（会复用已在 3306 的项目库） |
| 临时启用 MySQL80（其他库要用时） | 管理员窗口执行 `net start MySQL80` |
| 改回开机自启 | 管理员 PowerShell 执行 `Set-Service -Name MySQL80 -StartupType Automatic` |

注意：改为手动后，如果还有别的项目依赖 MySQL80 的库，那些项目开机不会自动连上数据库，需要用的时候再手动起。

## 单独启动数据库的命令

不想开窗口，也可以直接在命令行起项目实例：

```
"D:\develop\MySQL\MySQL Server 8.0\bin\mysqld.exe" --defaults-file="D:\develop\mysql-data\conf\ai-training.cnf" --console
```

加 `--console` 是为了让日志打在窗口里，关掉窗口即停库。去掉它则进程转入后台，需要用 `mysqladmin shutdown` 停止。
