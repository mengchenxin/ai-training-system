## 一、先记住这个骨架（所有模块都一样）

后端每个业务模块（`auth` / `system` / `skill` / `train` / `exam` / `ai`）内部都是固定的 4 件套：

```
module/train/
├── TrainPlanController.java      ← 接口层：只做参数校验 + 调 Service，不写业务
├── TrainPlanService.java         ← 业务层：真正的逻辑、事务、公式，都在这里
├── entity/                       ← 表映射：一个类 = 一张表
├── mapper/                       ← 数据访问：继承 MyBatis-Plus BaseMapper，基本是空接口
└── dto/                          ← 前端传进来的 / 返回给前端的 形状（不等于表结构）
```

**判断该看哪个文件的方法：**

| 你想知道 | 看哪里 |
| --- | --- |
| 这个功能有哪些接口、参数是什么 | `*Controller.java` |
| 业务怎么算的、数据库改了哪几张表 | `*Service.java` |
| 表里有哪些字段 | `entity/*.java` 或 `sql/01-schema.sql` |
| 前端发了什么、收了什么 | `web/src/api/index.ts` + `dto/` |

**一个请求的完整链路**（以"新增培训计划"为例）：

```
views/train/plan.vue          点保存按钮
   ↓ 调 planApi.save(data)
web/src/api/index.ts          url: "/train/plan", method: "post"
   ↓ axios，带 token
web/src/api/request.ts        拦截器加 Authorization 头；code!=0 就弹错误
   ↓ HTTP
SaToken 拦截器                 校验 token、校验权限
   ↓
TrainPlanController.save()    第 N 行：return planService.savePlan(form);
   ↓
TrainPlanService.savePlan()   写 train_plan + train_plan_course 两张表，@Transactional
   ↓
Result.success(id)            统一返回 { code:0, msg:"ok", data:id }
   ↓
request.ts 拆包 → plan.vue 拿到 id → 刷新列表 / 跳详情
```

**只要你能把这条链路背下来，项目就没有黑盒了。**

> ```
> gap          = max(0, target - current)          // 单技能差距
> weightedGap  = gap × weight                       // 按重要度加权
> matchRate    = 1 - ΣweightedGap / Σ(target×weight)  // 匹配度 0~1
> ```

> **`AiPlanService.generate()` 的 7 步**（这是论文第 5 章的骨架，必须能背）：
> ```
> 1. gapService.analyze(userId)        算技能差距        —— 纯算法
> 2. ruleEngine.plan(gap)              规则引擎出候选课程  —— 纯算法，确定性
> 3. ragService.search(...)            BM25 检索知识库    —— 纯算法
> 4. llmClient.chat(prompt)            调大模型（只做排序+写说明）
> 5. PlanSchemaValidator.validate()    结构校验，不过就重试
> 6. 失败则 fallback 到步骤 2 的结果    三级防御
> 7. writeRecord(...)                  写 ai_gen_record，可观测
> ```

**大模型只被调用 4 处**（不是 6 处，`PAPER_GEN` / `RETRAIN` 模板存在但没接线）：

| # | 场景 | 代码位置 |
| --- | --- | --- |
| 1 | 培训计划生成 | `AiPlanService.generate()` |

| 3 | 简答题判分 | `AiJudgeService.judge()` |
| 4 | 效果评估里的（若有）文字结论 | `EffectService` |

## 三、三条主线（按这个顺序读，一天一条）

### 主线 A：培训业务闭环（不碰 AI 也能跑通）

这条线是你**答辩时最可能被追问业务逻辑**的地方，也是全项目最"正统"的部分。

```
SkillGapService（算差距）
   ↓  gap 结果作为输入
TrainPlanService.savePlan（人工或 AI 建计划）
   ↓  状态机流转
TrainProgressService.report（员工上报学时）
   ↓  进度汇总
TrainProgressService.dashboard（看板 / 风险预警）
```

**读法**：进 `train/TrainPlanService.java`，只看三个方法就够：
- `savePlan(PlanForm)` —— 怎么把计划头 + 课程明细一起落库（事务边界）
- `changeStatus(id, status)` —— 状态机允许哪些跳转
- `detail(id)` —— 怎么拼 `PlanDetailVO`（计划 + 课程 + 进度百分比）

### 主线 B：AI 生成（论文的技术核心）

```
AiController.generate
  → AiPlanService.generate
      → SkillGapService.analyze       （复用主线 A）
      → RulePlanEngine.plan           ← 读这个，114 行，4 条选课规则
      → RagService.search             ← BM25，中文 2-gram 分词
      → LlmClient.chat                ← 看它怎么设超时、怎么发 JSON mode
      → PlanSchemaValidator.validate  ← 三级防御的中间层
      → writeRecord                   ← 可观测性，指标从这里来
```

**关键设计要能讲出来**：为什么不让大模型自由生成课程？
> 因为会编造不存在的课程、学时对不上。所以用**约束生成**：
> 规则引擎先框定候选集，大模型只在候选集内排序 + 写推荐理由。
> 这样"课程一定存在于课程库、学时一定不超预算"，而"叙述更自然"。

### 主线 C：考核与判分

```
ExamService.generatePaper（组卷：按题型/难度/知识点抽题）
   ↓
ExamService.start（开考：建 exam_record，发试卷）
   ↓
ExamService.submit（交卷 → 逐题判分）
   ↓  SHORT 题型
AiJudgeService.judge（给 AI 分数 + 参考分）
   ↓
写 exam_answer（AI 分、人工分分列存储，便于对比）
```

> `exam_answer` 同时存 `ai_score` 和 `manual_score`，这是"AI 判分可信度"的实验数据来源。

## 四、想验证自己看懂了？做这三个练习

| 练习 | 怎么做 | 说明什么 |
| --- | --- | --- |
| **1. 加一个字段** | 给 `course` 表加 `difficulty_new`，改 `Course.java`、`course.vue` 的表单和表格 | 你掌握了 entity ↔ 前端表单的联动 |
| **2. 改一条规则** | 在 `RulePlanEngine` 里把"学时上限"从 40 调到 30，重启看候选课程变少 | 你理解了规则引擎与 LLM 的边界 |
| **3. 断掉大模型** | 把 `application-local.yml` 里 `llm.api-key` 改错，再点 AI 生成 | 你会看到 `FALLBACK` 状态和规则兜底结果 —— 这就是"三级防御"的证据 |

第 3 个练习**强烈建议做**，答辩现场如果被问"大模型挂了怎么办"，
你可以直接打开 `ai_gen_record` 表指给他看失败记录和兜底结果。

## 五、答辩会被问的 5 个点 → 代码在哪

| 可能的问题 | 打开这个文件，指这一段 |
| --- | --- |
| 你的 AI 到底用在哪？ | `AiPlanService.generate()` 的 7 步；强调只有第 4 步是大模型 |
| 大模型生成不可靠怎么办？ | `PlanSchemaValidator` + `fallback()`；`ai_gen_record.status` 有成功率 |
| 技能差距怎么算的？ | `SkillGapService` 顶部注释里的三个公式 |
| 为什么用 BM25 不用向量库？ | `RagService` —— 无外部依赖、可解释、能给出引用来源；对课程文档这种短文本够用 |
| 你的系统和企业真实系统差在哪？ | 诚实说：单机部署、无 SSO、无审批流引擎、数据是造的 |

## 六、绝对不要做的事

- ❌ **不要从 `AiPlanService` 开始读**。它调了 6 个东西，你会立刻迷路。
- ❌ 不要试图一次读完全部 `entity`。表结构看 `sql/01-schema.sql` 更快。
- ❌ 不要纠结 `mapper/*.java`。它们都是空接口，方法全在 MyBatis-Plus 的 `BaseMapper` 里。
- ✅ 正确顺序：`AiTrainingApplication` → `common/Result` → `common/GlobalExceptionHandler`
  → 主线 A（train）→ 主线 B（ai）→ 主线 C（exam）。
