## 〇、开场先立住这一句

> "本系统面向企业内训场景，以**岗位技能差距量化**为数据主线，
> 打通「差距诊断 → 方案生成 → 执行跟踪 → 考核评价 → 补训」的闭环。
> 在方案生成环节用**规则排序 + 大语言模型**的混合策略做智能增强，
> 技术选型以**单机可部署、结果可控**为优先。"

这句话包含三个信息：做了什么、创新在哪、为什么这么选型。老师听完会顺着这三点问，都答得上来。

## 二、AI 亮点怎么讲（这是唯一需要讲深的地方）

### 讲法：三步走，先说"为什么不能只用大模型"

1. **先讲问题**
   > "如果直接把员工信息丢给大模型让它排课，有三个问题：课程可能不在课程库里（编造）、顺序可能违背先修关系、每次结果都不一样，没法复现也没法评价。"

2. **再讲混合策略**
   > "所以我做的是混合：**规则引擎负责'选什么课、什么顺序'，大模型负责'为什么这么排、怎么学'**。
   > 规则部分按加权差距排序召回候选课程，学时按差距大小分配；
   > 大模型只基于这批候选课程和真实差距数据生成方案说明与学习路径，不允许它自己加课。"

3. **最后讲可控性（这句最加分）**
   > "输出强制 JSON 结构，后端有 Schema 校验：课程必须存在于课程库、学时合计不能超预算、技能点必须来自差距表。
   > **校验不过就降级为纯规则方案**，AI 不可用时系统功能完整不中断。"

### 关键数字（一定背下来）

| 指标 | 实测值 |
| --- | --- |
| 培训前达标率 | **54.39%** → 培训后 **85.53%** |
| 加权差距 | **10.40** → **3.30** |
| 技能差距缩小率 | **61.63%** |
| 效果诊断结论 | EXCELLENT |

> 说这句：「这组数据是系统里跑完整闭环实测出来的，不是估的。」

### 如果老师问"你的大模型现在能用吗"

老实说：
> "当前环境没配 API Key，所以运行在 `AI_RULE` 规则模式，功能完整、结果确定。
> 配上 Key 就切到 `AI_HYBRID`。这也是我设计降级链的原因——演示环境不能依赖外网。"

这个回答比硬撑"能用"安全得多，而且反过来证明了设计合理。

## 三、三个技术点必须讲准（可能被追问）

**1. 差距量化公式**（写在论文里，能默写）

```
gap(i)         = max(0, target(i) − current(i))
weightedGap(i) = gap(i) × weight(i)
priority(i)    = weightedGap(i) / max(weightedGap) × 100
matchRate      = 1 − Σ weightedGap(i) / Σ(target(i) × weight(i))
```

排序：`加权差距降序 → 权重降序 → 技能ID升序`（保证结果稳定可复现，这句要说）

**2. 为什么权重很重要**
> "同样是差 2 级，核心技能的权重 5、辅助技能权重 1，培训优先级差 5 倍。没有权重的话，所有差距看起来一样急。"

**3. 闭环怎么闭的**
> "考试通过后技能等级回写档案，下次再算差距，达标率从 54.39% 涨到 85.53%——这就是闭环的验证方式。"

## 四、高频追问标准答法

| 老师可能问 | 你这样答 |
| --- | --- |
| **创新点是什么？** | "不是算法创新，是**应用层面的方法融合**：把技能差距量化结果作为约束条件喂给大模型，让生成方向由数据决定而不是模型自由发挥；再加结构化校验和降级，保证输出可用。" |
| **这和直接用 ChatGPT 排课有什么区别？** | "ChatGPT 不知道我们课程库里有什么课、每个员工差几级、预算是多少。我的方案是规则先限定可选集，模型只做解释和路径组织，输出还要过校验。" |
| **为什么不用 Redis / 微服务 / Docker？** | "单机部署、单人开发、数据规模在千级，引入这些只增加部署复杂度不带来收益。架构上预留了扩展位——比如检索层现在是内存索引，换向量库只改一个 Service。" |
| **工作量够吗？** | "六个模块、25 张表、80 多个接口、24 个页面，加上一套闭环验证脚本。核心工作量在差距量化和方案生成的可控性设计上。" |
| **数据哪来的？** | "构造的模拟数据集：员工 × 岗位 × 技能点，等级按正态分布生成。论文里会说明构造方法。" |
| **为什么不用 Spring AI / LangChain4j？** | "版本迭代快、兼容问题多，对我的论文没有加分。自己封装 HTTP 调用反而能控制重试、超时、降级这些真正影响可用性的部分。" |
| **主观题怎么评分？** | "客观题按标准答案精确匹配；主观题可选接大模型，按参考答案的要点覆盖率打分并给评语。没有 Key 时用二元组覆盖率做规则评分兜底。" |
| **系统的不足？** | 主动说两条："一是没有真实企业数据验证；二是主观题评分的准确性只做了抽检，没做和人工评分的一致性统计。"——主动认短板比被问出来好。 |

## 五、不要主动提的四样东西

菜单里已经隐藏了，老师不点就不说。**万一被翻到**，统一口径：

| 功能 | 一句话带过 |
| --- | --- |
| 知识问答 / 知识库 | "这是我额外做的可选扩展，用 BM25 词法检索，不在六个核心模块内。" |
| 群体短板分析 | "差距分析的一个聚合视图，按技能维度看部门整体短板。" |
| AI 效果指标 | "我给自己做的一个统计页，用来核对生成质量。" |

**绝对不要主动说"我做了 RAG"或"我用了向量检索"**——现在是 BM25 关键词检索，说成向量会被追问细节。被问到就答：
> "检索层用的是 BM25 词法检索，中文按 2-gram 切分建倒排索引。调研过向量方案，但千级片段规模下收益有限，还要多一个 Embedding 服务和向量库，部署复杂度不划算。"

这个回答是**加分**的，因为它体现了选型判断力。
