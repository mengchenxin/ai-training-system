## 五、必须补的三件事（按优先级）

### P0 — 补"纯大模型"对照组

开题和导师意见都明确要三组，现在只有两组。最小改法：

- 在 `AiPlanService.generate` 增加第三模式（如 `mode=PURE_LLM`）：**跳过 `RulePlanEngine` 的候选集约束**，把技能差距表直接喂给模型，让它自由生成课程清单；
- Schema 校验此时改为「宽松模式」：只校验 JSON 结构合法、课程能匹配到课程库，不再要求"必须在候选集内"；
- 复用现有 `exp_compare.py` 扩成三模式跑 20 个样本，指标加一项"幻觉课程数（生成的课程不在课程库中）"——这一项恰好能证明你的 Schema 校验有价值。

**这一步同时解决两件事**：三组对比齐了，且"为什么必须做约束"有了反面对照。

### P0 — 补方案合理性的人工评分

开题要求"方案合理性"维度，现在实验文档自述"未做人工评分"。做法：3～5 人盲评（隐去模式标签），5 分制，评"课程与差距匹配度 + 学时安排合理性 + 说明可读性"，算均值与 Kendall 一致性系数。20 个样本 × 3 组 × 5 人，一张表就能撑起一节。

### P1 — 补接口性能测试

写 3 个 JMeter 场景（登录、计划列表分页、AI 方案生成），各 50 并发，出响应时间与 TPS 表。开题的"主要接口 ≤ 2 秒"必须有数据支撑，这是"系统测试"章节的标配内容。

## 七、答辩预判：三个新风险

**Q：你的 RAG 用向量检索吗？**
A：如实答——知识片段 45 个、千级以内，采用 BM25 词法检索，离线、零依赖、得分可回溯；已在 `RagService.search` 预留向量混合排序扩展位。**不要答"用了向量库"**，开题写了但实现没做，答错会被追。

**Q：三组对比实验呢？**
A：目前两组，需要按 P0 补齐。这是导师明确点名的，空着风险最高。

**Q：系统里 Agent/工作流在哪？**
A：本项目没有 LangGraph 那类编排，走的是 Spring Boot 内自研的轻量编排（Service 顺序 + 状态字段 + 重试 + 降级）。这是开题"方案 B"，属于选定的路线，不是缺失。

**系统本身是达标甚至超预期的**——六个模块全通、AI 链路有校验有降级有可观测、闭环完整、代码 6752 行、25 张表、实验数据真实跑过 40 次。真正卡你的不是功能，是**开题承诺的三组对比只做了两组**，以及**开题的"向量检索"表述与实现的 BM25 不符**。这两点补上或改口径，系统就能完整支撑毕业设计说明书。
