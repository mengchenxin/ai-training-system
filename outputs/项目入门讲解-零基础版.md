# 项目入门讲解（零基础版）

> 目标：看完你能自己启动、能对着文件说出它管什么、能改一点代码看到效果。

## 一、这个系统到底在干什么

把它想成一家工厂的"培训管家"。

原来培训是：领导拍脑袋说"今年大家学安全生产吧"，全员一起看视频，看完签到，结束。
问题很明显——**学的用不上，学了也没人知道有没有用。**

这个系统改成了这样的流程：

```
① 先定义：这个岗位需要哪些技能、各要几级   （岗位技能模型）
        ↓
② 再看：每个员工现在几级，差在哪           （技能差距分析）  ← 系统核心
        ↓
③ 然后：按差距大小排优先级，生成培训方案     （AI 方案生成）
        ↓
④ 执行：员工学课、上报进度                  （进度跟踪）
        ↓
⑤ 验收：考试、前后测对比、算效果             （考核与效果评测）
        ↓
⑥ 闭环：没达标的生成补训方案，等级回写档案    → 回到 ②，重新算差距
```

**一句话概括**：把"凭经验的集体培训"变成"看数据的个性化培训"。

系统的技术含量全在 ② 和 ③ 这两步：② 是一套加权计算公式，③ 是把计算结果喂给大模型再管住它的输出。

## 二、怎么运行（先搞懂顺序，再动手）

### 三个东西，一条链

系统由三块组成，**必须按顺序启动**，因为后面的要连前面的：

```
MySQL（存数据）  →  后端 Java（算数据）  →  前端 Vue（显示数据）
 端口 3306            端口 8000              端口 3000
```

为什么必须这个顺序？

- 后端一启动就要连数据库，**MySQL 没起来后端直接报错退出**
- 前端只是个页面，它自己去请求后端，**后端没起来页面能开但全是空白和报错**

### 一键启动（推荐）

双击项目根目录的 **`start-all.bat`**。它会依次做：

1. 检查 3306 有没有在监听，没有就调 `start-mysql.bat` 启动项目专用 MySQL
2. 弹出一个黑窗口跑后端（8000）
3. 弹出另一个黑窗口跑前端（3000）
4. 探测两个服务是否正常，打印结果

**两个黑窗口都不要关**，关掉哪个就停哪个服务。全部停止 = 关掉这两个窗口。

### 分开启动（出问题时用这个，好排查）

| 脚本 | 干什么 | 窗口里能看到的成功标志 |
|---|---|---|
| `start-mysql.bat` | 起 MySQL | 打印 `ready for connections` |
| `start-backend.bat` | 起后端 | 打印 `Started AiTrainingApplication in x seconds` |
| `start-frontend.bat` | 起前端 | 打印 `Local: http://localhost:3000` |

### 打开系统

浏览器访问 **http://localhost:3000**

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `123456` | 管理员，什么都能看 |
| `lecturer01` | `123456` | 讲师兼主管，管计划和考核 |
| `emp001` | `123456` | 员工，只能看自己的 |

接口文档（写论文要截图）：**http://localhost:8000/api/doc.html**

### 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 后端窗口一闪就没了 | MySQL 没起来 | 先跑 `start-mysql.bat`，等它 ready 再跑后端 |
| 页面打开一片空白 | 前端没编译完或后端没起 | 等 10 秒刷新；看后端窗口有没有 Started |
| 登录提示"网络异常" | 后端没起 | 看 8000 端口是否在监听 |
| 端口被占用 | 上次的窗口没关干净 | 关掉所有黑窗口重来 |
| 第一次跑后端很慢 | 在打包 jar（mvn package） | 正常，等 1–3 分钟，之后就有缓存了 |

### 验证是否真的起来了

```bash
curl http://127.0.0.1:8000/api/ai/status
```

返回 `{"code":0,...,"mode":"纯规则降级模式（未配置 API Key）"}` 就说明后端活着。
（`code: 0` 是成功，不是 200，因为后端自己定义了返回格式。）

## 三、四层架构（数据怎么流动）

```
浏览器  localhost:3000          你点菜单、填表单
   ↓  HTTP 请求 /api/skill/gap/44
前端 Vue（Vite 3000）            页面、路由、发请求
   ↓  Vite 代理转发到 8000
后端 Spring Boot（Java 8000）    Controller → Service → Mapper
   ↓  SQL
MySQL（3306）                    25 张表
```

**中间那个"代理"最容易懵，说清楚它**：

前端代码里写的是 `/api/skill/gap/44`，不是 `http://localhost:8000/api/...`。
因为 `vite.config.ts` 里配了一条规则：所有 `/api` 开头的请求，都转给 8000。

好处是：以后部署到服务器换域名，前端一行代码都不用改。

## 四、目录地图（哪个文件管什么）

### 前端 `web/`

| 路径 | 管什么 | 什么时候会改它 |
|---|---|---|
| `src/views/` | **24 个页面**，一个 `.vue` = 一个页面（其中 16 个显示在左侧菜单） | 改界面、加页面 |
| `src/router/index.ts` | **路由表**：网址 ↔ 页面 ↔ 哪些角色能看。**左侧菜单就是从这里自动生成的** | 加菜单、改菜单名、控制权限 |
| `src/api/index.ts` | **接口清单**：每个按钮调后端哪个地址 | 加一个后端接口时 |
| `src/api/request.ts` | axios 封装：自动带 token、统一弹错误提示 | 一般不用动 |
| `src/layout/index.vue` | 外框：左侧菜单栏 + 顶栏 + 退出登录 | 改布局 |
| `src/stores/user.ts` | 登录状态：token、姓名、角色存在这里 | 一般不用动 |
| `vite.config.ts` | 端口 3000、`/api` 转发到 8000 | 换端口时 |

菜单为什么能自动生成？看 `layout/index.vue` 第 95 行：它读 `routes`，过滤掉 `menu: false` 的，再按路径前缀分组。所以**你只要在 router 里加一条，菜单就自动多一项**。

### 后端 `server/src/main/java/com/aitraining/`

| 路径 | 管什么 | 对应功能 |
|---|---|---|
| `module/system/` | 用户、部门、岗位、角色 | 模块① 用户权限 |
| `module/skill/` | 技能点、岗位技能模型、差距算法 | 模块② 技能差距 |
| `module/train/` | 培训需求、课程、计划、进度 | 模块③⑤ |
| `module/exam/` | 题库、组卷、考试、成绩 | 模块⑥ |
| `module/ai/` | 方案生成、评分、知识库、问答 | 模块④ |
| `common/` | `Result`（统一返回格式）、异常处理、分页 | 全局 |
| `config/` | 数据库、鉴权、接口文档、跨域配置 | 全局 |
| `security/` | 登录校验、角色判断 | 全局 |

### 后端每个 module 里都是同样四层（记住这个就够看所有代码）

以 `module/skill/` 为例：

| 文件 | 层 | 职责 | 类比 |
|---|---|---|---|
| `SkillController.java` | 接口层 | 收请求、取参数、调 Service、返回结果 | 前台接待 |
| `SkillGapService.java` | 业务层 | 真正算东西的地方 | 后厨 |
| `SkillMapper.java` | 数据层 | 只负责查/改数据库 | 仓库管理员 |
| `entity/Skill.java` | 实体 | 一个类 = 一张表，字段 = 列 | 货物清单 |
| `dto/GapResultVO.java` | 传输对象 | 返回给前端的数据长什么样 | 打包好的外卖 |

**规律**：Controller 不写算法，Service 不写 SQL，Mapper 不管业务。各干各的，所以改一处不容易坏别处。

## 五、一次点击的完整旅程（拿真实例子走一遍）

你在「技能差距分析」页面选了员工，点查询。背后是这 7 步：

| 步 | 文件 | 发生了什么 |
|---|---|---|
| 1 | `views/skill/gap.vue` | 下拉框选中 userId=44，点击查询触发函数 |
| 2 | `api/index.ts` | 拼出地址 `/skill/gap/44` |
| 3 | `api/request.ts` | 从 localStorage 取出 token，塞进请求头 |
| 4 | `vite.config.ts` | 把 `/api` 开头的请求转发到 `127.0.0.1:8000` |
| 5 | `SkillController.gap()` | 注解 `@GetMapping("/gap/{userId}")` 接住，取出 44 |
| 6 | `SkillGapService.analyze(44)` | 查 3 张表、套公式算差距和达标率 |
| 7 | 返回 `Result.ok(结果)` | 前端拿到 JSON，ECharts 画雷达图 |

**记住这个链条**：页面 → api 定义 → Controller → Service → Mapper → 表。
以后看任何一个功能，都按这个顺序找，一定能找到。

## 六、代码里那些"天书"怎么读

### 后端注解（`@` 开头的）

```java
@RestController                 // 这个类处理 HTTP 请求，返回值自动转成 JSON
@RequestMapping("/skill")       // 这个类里所有接口都以 /skill 开头
@RequiredArgsConstructor        // Lombok 自动生成构造函数
public class SkillController {

    private final SkillMapper skillMapper;
    // ↑ 注意：没有 new。Spring 启动时自动把对象"塞"进来，这叫依赖注入

    @GetMapping("/gap/{userId}")   // 收到 GET /skill/gap/44 就进这个方法
    public Result<GapResultVO> gap(@PathVariable Long userId) {
        //                              ↑ 从网址里把 44 取出来
        return Result.ok(gapService.analyze(userId));
        //     ↑ 包成 {code:0, msg:"success", data:...} 这个统一格式
    }
}
```

`@` 是"标记"的意思。你不用调它，Spring 启动时扫描这些标记，自动把类组装起来。你只要写业务逻辑。

### 后端常用返回格式

所有接口都返回同一个壳子，前端才好统一处理：

```json
{ "code": 0, "msg": "success", "data": 真正的数据 }
```

- `code` 为 **0 表示成功**（不是 200）
- `401` 表示没登录或 token 过期，前端会自动跳回登录页
- 其他数字表示业务错误，`msg` 里是中文提示

### 前端 `ref` 和 `onMounted`

```vue
<script setup lang="ts">
const rows = ref<any[]>([]);        // ref = "会变的数据"，一改页面就自动刷新

async function load() {
  rows.value = await skillApi.gap(44);  // await = 等后端返回再往下走
}                                        // .value 是 ref 的取值方式，别丢

onMounted(load);                     // 页面打开时自动执行 load
</script>
```

一句话：`ref` 管数据变化，`onMounted` 管"打开就执行"，`await` 管"等结果"。

## 七、核心算法：技能差距怎么算

只有四行公式，别被名字吓到：

```
差距(i)      = max(0, 目标等级 − 当前等级)      当前比目标高就记 0，不算负数
加权差距(i)  = 差距(i) × 权重(i)                重要的技能放大
达标率       = 1 − Σ加权差距 / Σ(目标×权重)      0% 全差，100% 全达标
优先级(i)    = 加权差距(i) / 最大加权差距 × 100   排序用，最大的是 100 分
```

**为什么要乘权重？** 同样差 2 级，核心技能权重 2.0、辅助技能权重 1.0，培训优先级差一倍。不乘权重，所有差距看起来一样急。

**真实算例**（陈静，质量工程师，系统实测）：

| 技能 | 目标 | 当前 | 差距 | 权重 | 加权差距 |
|---|---|---|---|---|---|
| 缺陷判定与原因分析 | 5 | 3 | 2 | 2.0 | 4.00 |
| 质量检验与测量 | 5 | 3 | 2 | 1.5 | 3.00 |
| 技术文档写作 | 4 | 3 | 1 | 1.2 | 1.20 |
| 其余 3 项 | — | — | 0 | — | 0 |

- 加权差距合计 = 8.20（这就是排序依据）
- 加权目标合计 = 36.10
- 达标率 = 1 − 8.20 ÷ 36.10 = **77.29%**

这个数字和系统接口返回的完全一致，说明公式没写错。

**代码在哪**：`module/skill/SkillGapService.java` 的 `analyze()` 方法（第 49 行开始，到 170 行左右）。类开头的注释里就写着这四行公式，可以先读注释再读代码。

## 八、AI 模块的原理（为什么不是"调个接口"）

### 只用大模型会有三个问题

1. **幻觉**：让它排课，它可能推荐一门你课程库里根本没有的课
2. **乱序**：可能把进阶课排在基础课前面
3. **不可复现**：同一个员工问两次，给出两个不同方案，没法评价也没法写论文

### 所以做成了混合

| 谁 | 干什么 |
|---|---|
| 规则引擎 | 按加权差距排序选课、按差距大小分配学时、控制总预算。**决定"学什么、什么顺序"** |
| 大模型 | 只基于这批候选课程和真实差距数据，写方案说明和学习路径。**决定"为什么这么排"** |

关键约束：**模型不许自己加课**。它只能解释和编排规则层给它的那几门课。

### 三道保险（这是设计亮点，答辩可以讲）

```
生成 → 是不是合法 JSON？ 否 → 降级
     → 课程是否都在课程库里？ 否 → 降级
     → 学时合计超预算了吗？ 是 → 降级
     → 全过 → AI_HYBRID（规则课程 + 模型说明）
```

降级后是 `AI_RULE` 模式：纯规则方案，**功能完整不中断**，方案里会写明降级原因。

**现在系统就运行在 `AI_RULE` 模式**，因为没配 `DEEPSEEK_API_KEY`。这不是缺陷，正是这套降级设计的意义——演示环境不依赖外网也能完整跑通。

想启用真 AI：在 `server/src/main/resources/application.yml` 第 66 行，把 `api-key: ${DEEPSEEK_API_KEY:}` 换成你的 Key，或者设一个同名环境变量，重启后端即可。

**代码在哪**：`module/ai/AiPlanService.java`，`generate()` 方法里能看到四个 `fallback(...)` 调用，那就是四条降级路径。

## 九、五个练手实验（改完立刻能看到效果）

按难度排序，前两个最安全：

**实验 1：改菜单名字（1 分钟）**
打开 `web/src/router/index.ts`，找到 `meta: { title: "技能差距分析" }`，改成 `"我的技能差距"`。保存，浏览器自动刷新，菜单名变了。

> 你会明白：菜单不是画出来的，是从路由表生成的。

**实验 2：看数据从哪来（3 分钟）**
登录后点「技能点管理」，新增一个技能点。然后用 Navicat 或命令行查：
```sql
SELECT * FROM skill ORDER BY id DESC LIMIT 3;
```
能看到你刚加的记录。**界面上的操作 = 数据库里的行**。

**实验 3：改权重看数字变化（5 分钟）**
```sql
UPDATE post_skill SET weight = 3.0 WHERE post_id = 5 AND skill_id = 1;
```
回到「技能差距分析」刷新，那个员工的加权差距和达标率都会变。
> 你会真正理解"权重"在公式里起什么作用。

**实验 4：加一个接口（20 分钟）**
在 `SkillController` 里加：
```java
@Operation(summary = "技能总数")
@GetMapping("/count")
public Result<Long> count() {
    return Result.ok(skillMapper.selectCount(null));
}
```
> 提示：如果 IDE 报 `@Operation` 找不到，是缺 `import io.swagger.v3.oas.annotations.Operation;`，
> 文件顶部已经有别的同类 import，照着补一行即可（不加这个注解也能跑，它只影响接口文档的显示）。

重启后端，浏览器直接访问 `http://localhost:8000/api/skill/count`（会提示未登录，说明鉴权生效了）。再到 Knife4j 文档里能看到这个新接口。
> 你会明白：加一个功能只需要"加一个方法 + 一个注解"。

**实验 5：加一个菜单页（30 分钟）**
复制 `views/skill/list.vue` 改名 `myDemo.vue`，在 router 里加一条：
```ts
{ path: "skill/demo", component: () => import("@/views/skill/myDemo.vue"),
  meta: { title: "我的试验页", icon: "Star", roles: ["ADMIN"] } }
```
保存，菜单自动多一项。
> 你会明白：页面、路由、菜单三者的关系。

1. **先跑起来**，用三个账号各登录一次，感受权限差异（员工看不到用户管理）
